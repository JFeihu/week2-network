## 1. 请求报文由哪几部分组成？

（提示：请求行 / 头 / 空行 / 体 —— 各写一句它负责什么）

请求报文包括四个部分：

1. 请求行：指定HTTP方法、请求目标、以及HTTP版本
2. 请求头：有多个 Key : Value 组成，表明请求的一些属性
3. 空行：表明请求头的结束，下面开始请求体
4. 请求主体：不是所有请求都有请求体，将请求数据发送到服务器，以便更新数据

## 2. `Host: 127.0.0.1:8000` 这行为什么必须有？

（提示：一个 IP 上可以跑多个网站，服务器靠什么区分）

一个IP地址有很多个网站，即使建立了连接，服务器也只知道有个客户端连接到了这个IP的xx端口，不知道客户端想要访问哪个网站。服务器要靠Host决定把请求交给哪个站点

## 3. 服务器的响应长什么样？

把你实验里看到的前 3 行粘贴过来：

```text
HTTP/1.0 200 OK
Server: BaseHTTP/0.6 Python/3.12.2
Date: Sun, 01 Nov 2026 08:03:16 GMT
Content-Type: text/plain; charset=utf-8
Content-Length: 18
```

解释 `HTTP/1.1 200 OK` 里的 `200` 含义，以及状态行为什么要单独一行。

200是响应报文中状态行的状态码，他表示请求成功。单独成行是为了方便机器解析；第一行的状态行，按空格分成三份，第一份是HTTP版本、第二份是状态码，给程序认的，第三份短语，描述状态码、给人看的附加信息

## 4. `Content-Length` 是干什么的？如果没有它会怎样？

表头表示发送给接收方的消息体的大小（以字节为单位），没有它只说明“长度没有用这个头来表达”。有它，客户端就能靠它给的值结束读取（结束到这么多字节数）没有它就只能通过别的方法，chunked 读到 `0\r\n\r\n` 结束；两个都没有，服务器回HTTP/1.0 客户端会一直读到连接关闭



## 5. `Connection: close` 和 `keep-alive` 有什么区别？

（提示：HTTP/1.1 默认是哪个？为什么默认复用连接）

HTTP/1.0   connection 默认值是 close ——一个请求一个连接、响应完就断开

HTTP/1.1  connection 默认值是 keep-alive —— 连接复用，同一个连接上可以发多个请求

为什么默认复用连接：建立 TCP 连接要三次握手（一个往返）、还要经历慢启动。如果每个请求都重连，在高并发下光建立连接就要耗费大量时间。一次连接多次请求，就可以省掉这部分的开销

```text
  ▼
浏览器渲染  
```
